Where disasters outrun insurance

Four KPIs on every US federal disaster declaration: what each type of disaster costs, how fast FEMA declares it, where households are left needing federal aid, and which states give insurers the most history to learn from. Change the filters and every chart and finding updates.

Financial KPI

Average federal payout per disaster

Total payout for a disaster type ÷ number of disasters of that type with a payout record

For insurers: types that are both costly per event and frequent create the biggest exposure. Price them first.

Internal process KPI

Weeks from incident to declaration

Declaration date − incident start date, averaged per disaster type

For insurers: slow-declared types leave time to assess damage; fast ones need claims teams ready on day one.

Customer KPI

Household aid activation rate

Disasters where FEMA activated aid to individual households ÷ all disasters of that type

For insurers: a high rate signals that people were left without enough cover. These are the gaps a new product could fill.

Learning & growth KPI

Predictive Disaster Learning Score

PDLS = 0.6 × frequency score + 0.4 × hazard-diversity score, each scaled 0–1 against the top state

For insurers: high-scoring states have enough varied history to price risk reliably; low-scoring ones need a surcharge for uncertainty.

    How this was built

    Data

    FEMA's open data API: DisasterDeclarationsSummaries (one row per declared county, reduced to one row per disaster) and FemaWebDisasterSummaries (federal money per disaster). A GitHub Action re-downloads both every week, so the numbers stay current.

    Definitions

    • Payout = Individuals & Households Program approvals + Public Assistance obligations (+ hazard mitigation if ticked). Public Assistance is split into emergency work (categories A–B) and permanent work. Only disasters with a FEMA payout record are averaged; older disasters have none, and counting them as $0 would understate costs.
    • Household aid = the Individual Assistance or Individuals & Households program was declared for at least one area of the disaster.
    • Declaration lag leaves out disasters with no start date or declared before the incident began (e.g. emergencies declared ahead of a hurricane).
    • PDLS compares every state and territory in the current filter.

    Origin and what changed

    This started as a four-person University of Twente project (Business Intelligence & Databases, Business IT), built in SQLite, Tableau and Orange on a fixed data extract. I rebuilt it as an open, interactive dashboard: a Python pipeline that pulls FEMA's live API, tested KPI code in JavaScript, and this page.

    Rebuilding it surfaced one fix: the original payout chart stacked emergency-work spending on top of total Public Assistance, which already includes it. On today's data that overstates total payouts by about 48% (nearly double for biological disasters). Here the channels add up to the total.

    New in the rebuild: filters by period, declaration type and state, a median option for declaration lag, small-sample hiding, and a slider to test the PDLS weighting instead of fixing it at 0.6.

    The same KPIs in SQL (dbt)

    Every week the raw FEMA rows also run through a dbt pipeline: SQL models from raw data to one row per disaster to the four KPIs, with data tests. One test fails if emergency work is ever counted on top of Public Assistance again. Two more check that the SQL pipeline and this page agree: on every field of every disaster, and on every KPI value. The page is only republished when those blocking tests pass; known quirks in FEMA's own records are logged as warnings.
